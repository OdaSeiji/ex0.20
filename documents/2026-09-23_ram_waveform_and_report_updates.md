# 2026-09-23 押出波形の押出日報連携、切出本数/ラック登録の改善、表示名整理

## 1. 押出日報に「押出波形」参照モーダルを追加

### 目的
`press_daily_report.html`の「ラム速度・圧力・温度」欄は手入力だが、実際にはPLCで
自動サンプリングされた`t_press_ram_log`に同じ内容の実測値がある。手入力の手間と
入力ミスを減らすため、実測値を参照・転記できるようにした。

### 内容
- 「ラム速度・圧力・温度」の右に🍓ボタンを追加。押すと「押出波形」モーダルが開く。
- モーダルは、押出日報の日付(`date__input`)と金型番号(`die__input`、例：`CA40T-V02C`)から
  対象を自動特定する。
  - 金型番号のハイフン前のベース名（例：`CA40T`）を取り出し、その日に`t_press_ram_log`へ
    記録されている`die_name`と完全一致するか確認。
  - 一致が1件なら自動選択。一致しない／複数ある場合は、その日に記録されている型番の
    候補一覧から選んでもらう（ラムログ側の型番表記は簡易的で完全には一致しないため）。
- 対象が決まると、その型番・日付の全ビレットについて、ラム位置1000/400/200mm時点の
  速度・圧力・温度（最も近い実測点、PLC生値を単位変換済み）を一覧表示する。
- モーダルの行をクリックすると、「ラム速度・圧力・温度」テーブル(`ram-values__table`)の
  No.1〜5のうち、一番上の空いている行へ自動転記する。
  - 実測ラム位置が1000mmに十分近ければ（誤差100mm以内）1000mm時点の値を、そうでなければ
    （短いビレットで1000mmまで届いていない場合）400mm時点の値を使う。200mm時点の値は
    常に200mm欄へ。
  - 転記済みの行はハイライトして見分けられるようにした。
- `ram-values__table`の各行（No.1〜5）の右端に✕ボタンを追加し、その行だけを個別に
  クリアできるようにした。

### 対象ファイル
- `php/press_ram_log/ram_log_api.php`（`summary`モードを追加）
- `press_daily_report.html`

## 3. 切出本数（旧：ビレット－切出本数）テーブルにコピー機能を追加

### 目的
同じ長さ・数量のレコードを続けて登録する場面が多いため、入力の手間を減らす。

### 内容
- `work-length__table`の「追加」ボタンの隣に「コピー」ボタンを追加。押すと、一番下の
  レコードの長さ・数量をそのまま複製して新しい行を追加する。
- レコードが1件も無いときはボタンを無効化。
- カード見出しを「ビレット－切出本数」から「切出本数」に変更。

### 対象ファイル
- `press_daily_report.html`

## 4. ラック登録カードに「本日の使用ラック数」を追加

### 目的
ラックは工場内で共有される有限の資材のため、同じ押出日に他のレコードも含めて
何本使われているかを、入力中の画面から確認できるようにしたい。

### 内容
- 「追加」ボタンの下に「本日の使用ラック数」を表示。
- 使用ラック数は、レコードごとの`t_using_aging_rack.order_number`の最大値（＝そのレコードで
  使ったラックの本数。数量(`work_quantity`)の合計ではない）を、押出日内の全レコードで
  合算したもの。
- 表示中の画面（保存前の編集内容を含む）の分は、DB側の合計から除外して二重計上を防ぎ、
  「DB上の他レコード分」＋「今の画面のラック表の行数」で算出する。
- 非同期リクエストの応答順序が入れ替わっても古い応答で上書きしないよう、リクエストに
  シーケンス番号を持たせた。

### 対象ファイル
- `php/press_daily_report/get_rack_total_for_date.php`（新規）
- `press_daily_report.html`
