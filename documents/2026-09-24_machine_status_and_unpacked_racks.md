# 2026-09-24 トップメニューに設備稼働状況を追加、未梱包ラック一覧（梱包入力の入口）を新設

## 1. トップメニューに設備稼働状況（No1/No2）を追加

### 目的
ex0.11（`diereport/ext0.11/exd11/index.html`）の右上にある号機ごとの稼働状況表示
（`#number1_status` / `#number2_status`）を、ex0.20のトップメニューにも移植した。

### 内容
- 「トップメニュー」の見出しの右側に、`No1: [型番]  No2: [型番]` を表示。
  見出しのセンタリングは変えず、ステータスは見出し行の右端に絶対配置している。
- データ元は ex0.11 の `SelPressStatus.php` と同じく `t_plc_web_log` の号機ごとの最新1行。
- 表示ルールは ex0.11 と同じ。
  - 最終記録が10分より古ければ `---`
  - `press_mode = 1`（稼働中）なら黄緑枠、それ以外は青枠
  - 1分ごとに自動更新
- ex0.11 からの変更点
  - 10分判定をサーバー側（MySQL の `TIMESTAMPDIFF(MINUTE, date_time, NOW())`）で行うようにした。
    ex0.11 は「ブラウザが日本時間なら2時間引く」という補正をJSでしていたが、
    DBサーバー時刻基準にしたことで閲覧する国に依存しなくなった。
  - 型番にマウスを乗せると最終記録日時をツールチップ表示（`---` になった理由の確認用）。
- 表示する号機は `get_machine_status.php` 冒頭の `$machines` 配列で指定（現在は machine 1 / 2）。
  DBには machine = 3 のデータもあるため、切り替える場合はここの数値を変える。

### 対象ファイル
- `php/machine_status/get_machine_status.php`（新設）
- `index.html`

## 2. 未梱包ラック一覧ページを新設（押出工程）

### 目的
ex0.11 の `PackingV1.html`（梱包入力）の移植に向けた第一歩。
ex0.11 はラックを最後まで梱包しなくても作業を終えられるため、梱包が残ったままのラックが
大量に残り、実際にどれだけ梱包の仕事が残っているか把握できない。
そこで、まず未梱包のラックを一覧化し、**ここから生産指示・ラックを選んで梱包作業を入力する画面の入口**にする。

### 未梱包の定義
ex0.11 の `SelUgingAgingRack.php` と同じ計算。

```
残本数 = t_using_aging_rack.work_quantity
       − NG本数（t_press_quality.ng_quantities の合計）
       − 梱包済み本数（t_packing_box.work_quantity の合計）
```

残本数 > 0 のラックを表示し、状態を2つに分ける。
- **未梱包**：梱包記録（t_packing_box）が1件もない
- **一部梱包**：梱包記録はあるが残本数が残っている

### 内容
- 押出日の期間指定（30/90/180日プリセット）、号機・状態・型番/品番キーワードで絞り込み。
- 集計カード：ラック数、残本数、未梱包/一部梱包の件数と本数、15日以上経過のラック数。
- 押出日からの経過日数を 0〜3 / 4〜7 / 8〜14 / 15日〜 で色分け。チップのクリックで絞り込み。
- **生産指示一覧**（age-bar の下）
  - 表示中のラックを生産指示（`t_press.ordersheet_id` → `m_ordersheet`）ごとにまとめた表。
  - 列：生産指示No、品番、型番、納期（過ぎていれば赤）、押出日（範囲と日数）、ラック数、残本数、
    最長経過日数、梱包済/指示数（指示全体の梱包進捗バー）。
  - 行クリックで、下の未梱包ラック一覧をその生産指示のラックだけに絞り込む（再クリックか「✕ 解除」で戻す）。
  - 押出日の古い順。`ordersheet_id` が空の押出は「（生産指示なし）」として最後にまとめる。
- 未梱包ラック一覧：列見出しクリックで並び替え、表示中の内容をCSV出力、日本語/ベトナム語切替。

### 実データで分かったこと（開発用DB、2026-09-24時点）
- 梱包記録が一度もないラックは毎年1,000件以上あり、直近30日でも497ラック・残り約16,000本。
- 生産指示の梱包進捗が100%（例：P260708184 は 425/425）なのにラックが残っている例がある。
  指示数ぶん梱包した時点で、残りのラックを閉じずに作業を終えていると思われる。
- 一部梱包で「残り1本」のラックが多い。ラックの本数と梱包本数の数え方の差による端数の可能性。
- `t_press.ordersheet_id` が空の押出（生産指示なし）が直近90日で203ラックある。
  生産指示を入口にする場合、これらの扱いを決める必要がある。

### 今後の検討事項
- 生産指示を選んだあとの梱包入力画面の形（同じページの下に入力欄を出すか、別ページへ遷移するか）。
- ラックを1つずつ選ぶか、生産指示の残りラックをまとめて梱包するか（現場の作業順を確認する）。
- ラックを「梱包完了（解放）」にする操作の追加。
- 性能：生産指示ごとの梱包済み本数の集計に時間がかかる（90日分で約1.6秒）。
  `t_press.ordersheet_id` にインデックスが無いのが主因。追加するかは未決定（DBに直接適用が必要）。
