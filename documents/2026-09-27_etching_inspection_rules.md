# エッチング検査の業務ルールと記録の仕組み（exd11 EtchingV4 の調査）

2026-09-27、品質評価入力（exd11 QualityReportV7）の ex0.20 移植を検討する中で、エッチング検査の画面と記録を調査した。
業務ルールは現場の説明（ユーザー確認済み）、数値はローカルDB（本番のコピー）の実データによる。

## 1. エッチング検査の目的

**ビレットの継ぎ目（溶着ライン）が、製品のどこまで影響しているかを見る検査。**
サンプルの位置の名前は、「継ぎ目が製品のどこに来るか」によって2通りある。

| 位置の名前 | 意味 |
|---|---|
| **nH / nE** | H＝製品の頭（Head）、E＝製品の尾（End）。継ぎ目をはさんだ製品の頭・尾。n は何番目の継ぎ目か |
| **nA / nB** | 押出材1本が2本のビレットで押し出されるとき、その途中にある2本のビレットの継ぎ目の両側 |

- 現場の説明：「1H：製品1本目の頭」「1E：製品2本目の尾」（1E が「2本目」で正しいかは未確認）
- 通常は1本のビレットから押出材が1本。複数のビレットで1本になるのは、重い押出材。

### 再検査のルール

ある位置で NG が出たら、**その製品1本を捨てて、次の製品の同じ位置を検査し直す。**
現場では、1H の再検査を「1H1」のように呼ぶ。

## 2. 画面と記録

exd11 のトップの「エッチング」ボタンが開くのは **EtchingV4.html**（EtchingV5.html もあるが、トップからはリンクされていない。主な違いはコードの書式）。

### 表（data__table）

```
VT（位置） | Lần 0（最初の検査） | Lần 1（再検査1回目） | … | Lần 4（再検査4回目）
          | ĐG（判定） | Lỗi（NGコード） | ĐG | Lỗi |     | ĐG | Lỗi
```

- 縦：サンプルの位置（28H、28E、1A、1B …）。位置の一覧は押出指示書（t_press_directive → m_nbn）から作っている（php/Etching/SelSide.php）
- 横：Lần 0 が最初の検査、Lần 1〜4 が再検査。**再検査の番号は位置の名前ではなく列で表す**（DB の Position に「1H1」のような名前は無い）

| `t_press_sub` | etching_finish（完了フラグ）, etching_staff, etching_check_staff, 画像, etching_note |
| `t_press.etching_check_date` | エッチングの完了日（php/Etching/InsEtchingDate.php） |

## 3. 実データで確認したこと

### 再検査の実態（2026年、位置ごと）

| 最初の検査 | 再検査1回目 | 件数 |
|---|---|---|
| OK | （なし） | 46,250 |
| NG | OK | 1,592 |
| NG | NG（さらに再検査） | 26 |
| NG | 空欄 | 8 |

最初に NG が出た位置は、ほぼすべて再検査されている。3回目の再検査まで進んだのは6件。

### A/B が使われる条件

1つの押出の中で H/E と A/B が混ざることがある（1,674押出）。A/B は 2022年3月から現在まで使われている。
A/B はほぼすべて **1つ穴の型** で使われていて、穴の数とは関係ない。

**号機に関係なく、「ビレット1本から押し出せる長さ」で分かれる。**（1つ穴の型、エッチングの記録がある押出）

| 号機 | 位置の名前 | 押出数 | ビレット | 製品 kg/m | ビレット1本から押し出せる長さ |
|---|---|---|---|---|---|
| 1 | H/E だけ | 4,590 | 9インチ × 873mm | 2.5 | 約45m |
| 1 | A/B を使う | 1,107 | 9インチ × 1,165mm | 6.9 | 約20m |
| 2 | H/E だけ | 513 | 13.4インチ × 1,198mm | 9.1 | 約38m |
| 2 | A/B を使う | 493 | 13.8インチ × 1,200mm | 17.9 | 約20m |
| 3 | H/E だけ | 545 | 9インチ × 793mm | 1.9 | 約55m |
| 3 | A/B を使う | 70 | 9インチ × 1,144mm | 6.3 | 約22m |

長さの見積もり：ビレットの体積 × アルミの比重 2.7 ÷ 製品の kg/m

- ビレット1本から約20mしか押し出せない押出で A/B、40m前後以上なら H/E だけ。
- 「重い押出材は複数のビレットで1本」の「重い」は、**ビレットの大きさとの関係** で決まる。2号機は製品自体が重い（17.9 kg/m）ため A/B の割合が高い（エッチングの記録がある押出の49%）。1号機は 9インチのビレットに対して重めの製品（6〜7 kg/m）で A/B になる（件数は1号機が最多の1,111押出、割合は18%）。

1号機で A/B が多い型番の例：XLA25B2-V01B / V02B、XLA40B2-V01B、MSQ50B2-V02D、MGPM25B2-V01D、MGPM40B2-V01D、SY50MP-V01D、MSQ30B2-V03D、SY70M-V01B、PS63-V01D など（全97型番）。

## 4. 品質評価（t_press_quality）との関係

- エッチングの画面：**サンプルの試験結果**（どの位置が合格か、何回再検査したか）
- 品質評価の画面の工程 Etching（process_id = 2）：**その結果、ラックの何本を NG にしたか**

同じ工程でも記録している中身が違うので、二重入力ではない。
エッチングの完了日（etching_check_date）はエッチングの画面で入れるので、品質評価の画面では表示だけにする方針。

## 5. 問題点・未確認事項

- 判定の選択肢・NGコードが JS に直接書かれている（m_quality_code の id を直書き）。ex0.20 では、どの工程でどのコードを使うかをマスタで持たせたい。
- `m_quality_code` で 311 と 312 が両方「エッチング不良」、313 の日本語が中国語（粘铝不良）。
- 完了日を保存する PHP（InsEtchingDate.php）が、値を SQL に直接埋め込んでいる（SQL インジェクションの穴）。
- 未確認：「1E：製品2本目の尾」で正しいか、判定の Rút・BH の意味。
