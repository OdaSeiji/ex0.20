# 2026-09-27 品質評価入力（quality_report.html）の新設

exd11 の QualityReportV7（品質評価入力）のリファイン版として、ex0.20 に品質評価入力を新設した。
トップメニューの「品質」セクションに、品質サマリーと並べて置いている。

## 1. このページの役割

**押出（t_press）を選び、ラックごとに、ラックの本数に対してどの不良コードが何本出たかを記録する。**

- 不良は、どの工程（寸法・エッチング・時効）で見つけたか、判定者、備考と一緒に `t_press_quality` に記録する。
- 実データでは、各工程の評価が終わるたびに、その工程の NG が入力されている
  （複数工程に NG がある押出の69%は工程ごとに別の日。寸法の NG は寸法の完了日と同じ日、エッチングは約1日後、時効は約1.6日後）。
  3工程のまとめを入力する画面ではなく、各工程の担当者が結果を記録していく共通の画面。
- 寸法の完了日はこの画面で入れる。エッチングの完了日はエッチングの画面、時効の完了日（hardness_check_date）は硬度の画面で入れ、この画面では表示のみ（二重入力しない）。
- 必要な工程がそろったら、QC の担当者が確認して「意図して」完了にする（自動では完了にしない）。

## 2. 画面の仕様

### 押出の選び方（左の一覧）
- プレス種別のタブ：● / ◎ / 〇（件数付き）
- 「未完了」「完了済み」の切り替え
- 表示するのは **押出日が今日から1か月前まで** の押出。1か月を過ぎた押出は一覧から消え、旧画面（exd11 QualityReportV7）で扱う
- 一覧には、工程ごとの状況（寸法・エッチング・時効・QC の ✅⬜、〇 はエッチング・時効が「－」）、経過日数、NG 本数、一覧から消えるまでの「あと◯日」（7日以内）を表示
- V7 は日付＋型番で探して1件目を取るため、同じ日に同じ型を2回押すと2回目を選べなかった。一覧から押出そのものを選ぶので解消

### 種別ごとの要求
| 種別 | QC の前に必要な工程 |
|---|---|
| ●・◎ | 寸法・エッチング・時効 |
| 〇（テスト） | 寸法のみ |

〇 で本当に寸法だけでよいかは、標準化が必要な課題として残している。

### NG の入力（右）
- ラックを選ぶ（順・ラックNo・本数・NG・OK を表示。ラックの本数の変更・削除は押出日報で行う）
- 工程（寸法・エッチング・時効）、コード（番号を打つと選択肢が合わせて動く）、本数、判定者、備考 → 追加
- **コード「0 不良なし」**：本数0で記録する。NG が無かったラックでも「誰がチェックしたか」が残る記録で、寸法では2026年だけで1,217押出に使われている
- 記録した NG は、行をクリックすると修正・削除できる（完了後も可能。V7 と同じ）
- 押出全体の NG コード別の合計を表示

### 入力のルール
- NG コードは全コード（301〜351、401）と「0 不良なし」
- 本数は1〜500の整数（コード0は0に固定）
- **ラックの NG 合計（寸法・エッチング・時効）がラックの本数を超える入力は保存できない**（V7 はチェックしていなかった）
- 判定者・QC の確認者は、**在籍中の検査員**（m_staff の role = 'inspector' かつ leave_at が空）から選ぶ。admin の人が入力する必要がある場合は、m_staff の役割を直す
- 1か月より前の押出への書き込みは、サーバー側で拒否する（旧画面で扱う）

### QC（最終確認）
- 必要な工程の完了日がそろうまで「確認して完了にする」は押せない（サーバー側でも確認）
- 確認日と確認者を入れて完了にすると、`qc_check_date`・`qc_staff_id` に保存し、ex0.11 の画面でも確認済みに見えるよう `qc_check_id = 1` も入れる
- 完了は取り消せる（取り消すと未完了の一覧に戻る）
- QC では OK / NG の判定はしない。不合格品はラック単位の NG 記録で残し、除いて納品する

### ex0.11（V7）と並行運用している間の扱い
- V7 で QC を完了にした押出は `qc_check_id` だけが入る。`qc_check_date` が空でも `qc_check_id` が入っていれば完了済みとして扱い、「旧画面（V7）で確認済み」と表示する
- V7 の QC 担当者（qc_name_id）は画面だけの番号（1〜4、m_staff とは無関係）なので、ex0.20 では使わず、新しい列 `qc_staff_id` に m_staff の id を保存する

## 3. DB変更

| SQL | ローカル | 本番 |
|---|---|---|
| `t_press.qc_check_date` の追加 | 実行済み | **未実行** |
| `t_press.qc_staff_id` の追加（m_staff への外部キー付き） | 実行済み | **未実行** |

**コードの反映より先に実行すること**（無いと一覧・詳細の読み込みがエラーになる）。

```sql
ALTER TABLE t_press ADD COLUMN qc_check_date DATE NULL AFTER qc_name_id;
ALTER TABLE t_press
  ADD COLUMN qc_staff_id INT(11) NULL AFTER qc_check_date,
  ADD KEY idx_press_qc_staff (qc_staff_id),
  ADD CONSTRAINT fk_press_qc_staff FOREIGN KEY (qc_staff_id) REFERENCES m_staff (id);
```

確認用：
```sql
SHOW COLUMNS FROM t_press LIKE 'qc%';
```

## 5. 残した課題

- NG を修正できる人の制限：誰でも修正・削除できる（V7 と同じ）。ex0.21 のログイン制で修正者を制限するのが本来の姿
- 工程ごとに使う NG コードの絞り込み（m_quality_code に工程の情報が無い）
- 〇（テスト）押出で必要な評価の標準化
- `aging_check_date` 列の削除（ex0.20 への移行完了後）
