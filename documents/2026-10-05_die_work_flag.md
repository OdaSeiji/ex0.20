# 2026-10-05 金型の作業（t_die_work）と金型の旗（t_die_flag）を新設

## 目的

金型の次の作業管理（押出のあとの洗浄・研磨・修理・窒化・ラックへ を追う管理画面）のため。
今の `t_dies_status` は「○○した」という出来事を1行ずつ記録するだけで、作業の**開始と終了**が分からず、
「やらなくてはいけないこと」と「どこまで終わったか」が見えない（プレス後待ち 312型のうち 187型は押出から3か月以上、研磨の記録は 2026-03 から止まっている）。

## 業務の流れ（ユーザーと整理、2026-10-05）

```
押出
 ├─(洗浄しない)─────────────────────────→ 金型ラックへ
 └─(洗浄する)→ 洗浄[開始→終了] → 研磨[開始→終了] → 金型ラックへ
                                 └(寸法 NG のとき)→ 修理[開始→終了] → 金型ラックへ
窒化：別のルールで判断（DieMaitenanceV3）→ 窒化 → 金型ラックへ
```

- すべての工程に開始と終了。ラックの場所は今は記録しない。現場のタブレットで使う想定
- **OK／NG は工程ではなく、金型の状態の旗**（ユーザー）。NG の旗が立った金型は、必ず洗浄が必要

## 設計

`t_dies_status` の役割を2つに分ける。

| テーブル | 役割 | 1行 |
|---|---|---|
| `t_die_work` | 作業：洗浄・研磨・修理（ワイヤーカット）・窒化・測定・ラックへ | 1つの作業（開始〜終了）。`ended_at` が空なら作業中 |
| `t_die_flag` | 金型の旗：NG（洗浄が必要）・NG Rz/Die mark・NG 寸法 | 旗を立ててから下ろすまで。`cleared_at` が空なら旗が立っている |

- 作業の種類・旗の種類は、どちらも `m_die_status` の id を使う
- `press_id`：きっかけになった押出
- 旗を下ろしたときは、きっかけになった作業（洗浄など）を `cleared_work_id` に残す
- 一瞬で終わるもの（ラックへ）は、開始と終了を同じ日時にする
- `entry_source` と `legacy_status_id`：`t_dies_status` から昔の記録を移すときに使う（0＝移した記録、1＝ex0.20）
- 写真：今は `file_url`（1枚）だけ。複数枚が必要になったら別テーブルを足す（ユーザー判断。参考：今は `t_dies_status_filename` に複数枚の写真がある）

`t_dies_status` は、ex0.11 が使われている間は残す（ex0.11 の WashingTank は今も使われている。`t_washing_tank` が 10/1 まで更新）。
